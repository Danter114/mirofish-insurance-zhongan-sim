# 采集层 · 从「给一个主题」到「21 字段原始帖」

**一句话**：采集侧给的那套爬取流程，现在**在这个交付里能跑、能看、能接** ——
不是一页说明文档，是 `python 采集链.py` 一条命令真的产出 `EV1_raw.json`，
而且回放出来的 3 条与采集侧正式数据 **21 个字段逐字段 0 差异**。

```
python 采集链.py --mode snapshot --card EVT-001_宠物险广告低俗\EVT-001_参数卡.json `
                  --snapshot-dir EVT-001_宠物险广告低俗\原文快照 --out 输出目录
```

---

## 一、先说清楚一件事：原来为什么没做进去

这不是"漏了"，是三层原因，其中只有第一层是我们的问题：

| # | 原因 | 现在的处理 |
|---|---|---|
| 1 | **采集侧自己也没接平台 API**。`采集侧全流程说明.md` §七 原话：平台官方 API 全量采集 = **无**，接入方式是「人工 + AI 辅助检索」，API 配置项仍为空 | 交付里**如实写着**这一条，不包装成「我们有 API 采集」 |
| 2 | **那个爬虫程序就算拿到也只覆盖一个渠道**。`使用说明.md` / `一键演示.py` 都调用 `D:\数据采集\yuqing_collector.py`，但它既不在资料包里也不在这台机器上；而 `采集链路说明.md` 写它的真实能力只有「实时新闻采集（百度资讯解析 + 验证码退避）」—— 6 个渠道里的新闻门户那一个 | 按 `采集规则.md` 把**快照回放**这一段重建为 `采集链.py`；新事件的检索用 `检索作业.py` 开单/收单规范化（见 §四），并从资料包里补齐其余全部程序与文档 |
| 3 | **实时抓取天然不可复现**。平台要登录态、会弹验证码、会删帖，同一条命令两次跑出来的条数不一样 —— 采集侧自己也是因为这个才把「快照回放」定成现场演示主路径 | 把实时抓取接成**可插拔适配器**（见 §四），接上就能跑，跑不了会**明确报错**，不静默返回空 |

> 所以本项目对外的口径应该是这句：**采集链已经打通到「拿到候选帖就能出标准事件包」**；
> 再往上一寸（平台登录态 + 各渠道解析）依赖外部爬虫或平台接口，接口位已经留好。

## 二、这一层能跑什么（本机实测）

| 模式 | 干什么 | 现在能不能跑 | 需要什么 |
|---|---|---|---|
| `--mode card` | 主题 → 事件参数卡（8 类枚举强制，`参数卡生成.py`） | ✅ | 有 key 走 LLM，无 key 走规则兜底最小卡 |
| `--mode snapshot` | 快照回放：三层硬过滤 → 21 字段 raw → 采集日志 | ✅ **零依赖、离线、~0.1 秒** | 参数卡 + 快照目录 |
| `--mode api` | 委派你自己写的适配器（平台 API / 现成爬虫 / 数据库） | ✅ 自带可运行样例 | `--adapter 你的.py` |
| `--mode live` | 委派真正的爬虫 `yuqing_collector.py` | ❌ **缺程序**（会打印该放哪儿） | `--collector <路径>` 或 `$env:YUQING_COLLECTOR` |

随时可以用 `python 采集链.py --check` 看这台机器上四种模式的真实可用性（JSON，不猜）。

**一条命令看全链**（快照回放 → 结构化标注 → 舆情看板）：

```powershell
python 一键演示.py --card EVT-001_宠物险广告低俗\EVT-001_参数卡.json `
    --snapshot-dir EVT-001_宠物险广告低俗\原文快照 --out ..\..\_运行\采集层试跑 --no-llm
```

实测 0.7 秒，产物：`EV1_raw.json`（21 字段 / 3 条）→ `EV1_processed.json`（28 字段 / 3 条）
→ `EV1_舆情看板.html`（单文件，零外部依赖）→ `采集日志.jsonl`（逐帖一行，保留/丢弃各有理由）。

## 三、回放是**真的**回放，不是复制

`--mode snapshot` 走的是 `采集规则.md` 里写死的那套规则，一条都没加：

1. **窗口**：`publish_time` 的日期必须落在参数卡的 `start_date ~ end_date`
2. **排除词**：正文命中 `exclude_words` 任一词 → 丢
3. **必选词**：正文必须命中 `keywords` / `aliases` / `subject` 之一 → 否则丢
4. **垃圾**：正文为空、正文含手机号/身份证号 → 丢（垃圾 8 类里唯一两条能靠正则判死的）；
   **拿不准的一律保留**（原文："只删除明确命中上表的内容"）
5. **去重**：同一 `post_id` / 同一 URL 只收一次

字段取值顺序 = **`snapshot_meta.json` 的金标准值优先，参数卡只兜底**
（这是 `采集链路说明.md` §四.2 定的，不是我们改的）。

**验收**（可在 `_自检\自检_采集层.py` 里一条命令复跑）：

```
--capture-date 2026-10-01 回放 → 与 EVT-001_raw.json 比对 → 21/21 字段逐字段一致
```

唯一按设计会变的是 `capture_date`（抓取日期 = 运行当天）。交付样本里已把它固定成
正式数据那天的日期，所以比对是 0 差异；不传 `--capture-date` 就是今天 —— 两种都对。

## 四、新事件：检索作业（开单 → 按单落档 → 收单）

前面三节说的是「**有快照回放**」。这一节说的是「**给一个新主题，怎么把那批快照弄出来**」——
这一段在采集侧是**人工 + AI 辅助检索**（`采集侧全流程说明.md` §七：平台官方 API 全量采集 = 无），
交付里不假装有爬虫，而是把它做成**可开单、可验收**的作业：

```
开单  ──→  照《检索作业单.md》检索、打开原文、落档  ──→  收单（校验）──→ 采集链 ──→ EV<n>_raw.json
```

### 4.1 开单

```powershell
python 检索作业.py 开单 --card 参数卡.json --out 作业目录\EVT-014
```

产出四个空壳，都是**照采集侧既有格式**做的：

| 文件 | 内容 |
|---|---|
| `检索作业单.md` | 这一单要什么、6 个渠道的建议检索串与已知坑、落档三件套的格式、一段可直接粘进带浏览器 AI 的检索指令（**我方拟的通用版**，标注了不是采集侧原文） |
| `查询记录.csv` | 8 列 × 6 渠道预填（`channel/query/queried_at/result_count/opened_count/kept_count/drop_reason/note`） |
| `采集清单.json` | `[]`，按作业单 §4.3 的 8 个键逐帖填 |
| `原文快照\` | `snapshot_meta.json`（`[]`）+ `_格式说明.txt`（四行头样例） |

### 4.2 收单

```powershell
python 检索作业.py 收单 --job 作业目录\EVT-014 --card 参数卡.json --out 输出目录 --collect
```

**12 项检查，硬性项 exit 1**。其中三项是这一支真正的价值：

- **H1d 快照非空**：0 条不算收单成功 —— 空快照在下游每一道闸上都"能过"
  （条数 0==0、覆盖集是空集），不在这里拦就会一路绿灯跑到 `raw = []`，看着像"采到 0 条"
- **H8 对账**：`查询记录` 的 `kept_count` 合计必须等于快照实际条数 —— 防止"表里写留了 5 条、实际交 3 条"
- **H9 清单即全集**：`采集清单` 必须覆盖快照里的每一帖 —— 这是 `采集规则.md` §六 的口径

其余：meta 的 file 存在、渠道在 6 类内、post_id 唯一、6 渠道每个都有记录行、8 列齐全；
警告项（不判失败）：txt 缺四行头、`query`/`result_count` 没填、缺 `post_url`、清单里有多余条目。

`--collect` 只是顺手调一次 `采集链.py --mode snapshot`，**过滤口径仍然只有那一份**，没有第二套规则。

### 4.3 实测（`_自检\自检_采集层.py` 第 [6] 组）

用 EVT-001 的现成快照当"这次检索的成果"填进去：开单 → 填 → 收单 → raw，
与采集侧正式 `EVT-001_raw.json` **3 条 × 20 字段逐字段一致**（`capture_date` 按设计是运行当天）。
再把 `查询记录` 里的「监管通报」整行删掉、把小红书的 `kept_count` 从 2 改成 1 ⇒ 收单 **exit 1**，
并分别点名「缺：监管通报」「记录里 2 条，快照里 3 条」。

### 4.4 这一支**不做**什么

- 不判断检索做得对不对（相关性是人的判断），只判断「交上来的东西齐不齐、自不自洽」
- 不自带浏览器、不调模型 —— 交付是内网零依赖的，检索留在外部跑，产物喂进来
- 作业单里那段 AI 指令**是我方照 `采集规则.md` 重写的等价版**，不是采集侧真实用的提示词；
  真实提示词已经在 `端到端逻辑\采集侧爬取接口需求\03_接口契约\AI检索规程_模板.md` 里向他们要

## 五、怎么把实时抓取接上（这是给后面那个人看的）

### 路线 A：你有现成爬虫 → `--mode live`

```powershell
python 采集链.py --mode live --card 参数卡.json --out 输出目录 --collector D:\数据采集\yuqing_collector.py
```

它必须支持这两个参数（与快照回放同一套，`一键演示.py` 也是这么调的）：

```
--mode live --card <参数卡.json> --output-dir <输出目录>
```

跑完要在 `<输出目录>` 里落 `EV<n>_raw.json`（21 字段）。**没找到程序或没落文件，采集链都会报错退出**，
不会返回一个空数组让你以为"采了 0 条"。

### 路线 B：你有平台 API / 自己的采集服务 → `--mode api`

抄一份 `采集适配器_模板.py`，只改 `fetch(card)` 的函数体：

```python
def fetch(card):
    # 拿 card["keywords"] / card["start_date"] 去问你的数据源
    return [{"content": "...", "publish_time": "2026-05-21 20:30",
             "channel": "微博", "post_url": "...", "author_name": "..."}, ...]
```

**契约只有两条**：返回列表里每条至少要有 `content` / `publish_time` / `channel`（6 类枚举之一）；
过滤不归适配器管 —— 窗口、排除词、必选词、去重、隐私由采集链统一做，
口径只有一份，别在适配器里再写一遍。

自带样例 `adapter_sample.json` 四条帖，故意埋了三种弃样，跑一遍能看到过滤器真的在工作：

```
✅ 采集完成（api）：保留 1 条 / 丢弃 2 条
   - 丢弃 EV1_WB_902：窗口外（2026-05-25 不在 2026-05-21 ~ 2026-05-22）
   - 丢弃 EV1_NEWS_904：命中排除词「宠物店」
   （第 4 条 channel=知乎 不在 6 类枚举内，适配器直接不收）
```

### 接好之后接哪儿

`POST /api/collect/run`（后端）与 `http://127.0.0.1:5001/collect`（采集控制台）会
自动读到新的可用性 —— 控制台上「实时抓取」那一格从灰色变成可用，不用改前端。

## 七、边界（照实写）

1. **`--no-llm` 的标注是规则兜底，不是真标注**。情感靠 14 个负面词表，命中即负面、否则中性 ——
   实测与人工标注一致率约 **44%**（采集侧自述）。要保真必须配 `LLM_API_KEY` 跑
   `build_event.py`（4 线程并发 + 按 post_id 缓存，重跑秒回）。
2. **参数卡生成器把接口地址写死在源码里**（`https://api.deepseek.com/v1`，模型 `deepseek-v4-flash`），
   不像本后端那套走 `LLM_BASE_URL`。换服务商要改它源码 —— 这是采集侧的既有实现，交付里没有改动。
3. **`采集适配器_模板.py` 的样例数据源是本地 JSON**，不是真抓。它的价值是**证明接口位可用**，
   不是证明"我们能爬微博"。
4. **样本只有 EVT-001 一场**（3 条）。要看 29 条那一批，去 `04_事件一_采集到报告全量数据\01_采集\`。
5. **`采集过程演示.html` 是进度演示页**（步骤与数字是真实的，推进是按时间轴走的），
   它的定位是"给评委看流程长什么样"；真想跑，用上面的命令行或 `/collect` 控制台。
