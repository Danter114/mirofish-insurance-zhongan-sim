## 一、链路总览

```
主题（模糊词）
  │ 参数卡生成.py（LLM 生成 8 类枚举参数卡；无 key 时规则兜底）
  ▼
参数卡（event_id/名称/类型/窗口/主体/别名/检索词/排除词/话题/主题词）
  │ 采集：① 快照回放（固定采集清单 URL 锁定，现场演示主路径，0 差异复现）
  │      ② 实时检索（新闻门户百度资讯，活体证明，验证码自动退避）
  ▼
raw（21 字段，原文快照 + snapshot_meta.json 金标准值）
  │ build_event.py（规则角色 + LLM 并发标注[4线程+缓存] + 口径仲裁 + 8 类校验）
  ▼
processed（28 字段事件包）──┬─→ evt_dash_builder.py + 文案包 → 舆情看板 HTML
                            └─→ 下游知识图谱侧（建图/定槽位/选人）
评测闭环：评测基准集（人工标注）↔ evaluate_sentiment.py ↔ 情感识别评测报告
```

## 四、复现机制（给命题组的口径）

1. **历史事件复现 = 固定采集清单**：`EVT-00N_采集清单.json` 把采集目标锁定到 URL/平台原生 ID 级，
   清单即全集——按清单核验并存快照，**没有新增也不会缺失**；不通过关键词搜索召回（平台排序/删帖
   会导致结果漂移，这是平台能力边界，不是采集口径问题）。
2. **快照回放 = 规则执行**：`yuqing_collector.py --mode snapshot` 对清单跑完三层硬过滤与 21 字段组装，
   快照清单保存采集时的逐帖金标准值（topic_tag/topic_list/keyword_match/互动量），参数卡只兜底。
3. **实测**：事件 1（3 条）与事件 13（8 条）回放产物与正式数据**逐字段 0 差异**（capture_date 为运行日，
   属预期）。
4. 新事件采集：用参数卡生成器 + 6 渠道检索，平台封闭白名单保证口径一致；数据一旦冻结即生成
   固定采集清单，此后以清单为准复现。
