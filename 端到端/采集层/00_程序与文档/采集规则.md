# 舆情 raw 数据采集规则

> 用途：给定一个新事件，按本规则采集公开帖子，输出 21 字段 raw JSON/CSV。

## 一、事件参数

采集前先把下表填完，后续检索、筛选、命名都以它为准。

| 参数 | 填写说明 |
| --- | --- |
| event_id | `EV` + 事件序号 |
| event_name | 事件简称 |
| event_type | 事件类型 |
| start_date / end_date | 采集窗口 |
| subject | 核心主体 |
| aliases | 主体别名、产品名、关联公司 |
| keywords | 检索词，含事件特征词、独特事实词 |
| exclude_words | 撞名企业、无关产品、招聘/广告等排除词 |

## 二、渠道

| channel | 适用范围 |
| --- | --- |
| 微博 | 微博原帖 |
| 小红书 | 小红书笔记 |
| 抖音 | 抖音视频 |
| 新闻门户 | **封闭白名单（平台定死，清单外不收录）**：新浪财经、凤凰网、澎湃新闻、界面新闻、蓝鲸财经、财新网、36氪、虎嗅、每日经济新闻、证券时报、第一财经、21世纪经济报道、中国网财经、荔枝网（江苏广电）、中国吉林网、深圳新闻网、腾讯新闻、中华网、金融界、红星资本局、都市快报、新京报、大众日报、上海热线、财联社。清单外的媒体来源一律不收录（进待确认清单备查，不擅自扩充） |
| 黑猫投诉 | 黑猫投诉平台的投诉页 |
| 监管通报 | **封闭白名单（平台定死，权威等级相当于中央发文）**，仅限两类：① 中央部委/监管机构官方渠道：中国政府网、国家金融监督管理总局（原银保监会）、中国人民银行、市场监管总局、网信办、沪深交易所；② 党央媒官方渠道：人民日报、新华社（新华网）、央视（央视网/央视新闻）、央广（央广网）、光明日报（光明网）、经济日报（中国经济网）、中国新闻网（中新社）、中国网、人民网、中国日报、求是、法制日报，含其转载中央级媒体原文的权威转载（如人民网法治频道转载《法制日报》）。**白名单外的任何来源（地方媒体、商业网站、自媒体）一律不归监管通报**；地方、商业媒体转载中央报道的归「新闻门户」（且该媒体本身需在新闻门户白名单内，否则不收录） |

`channel` 只能取这 6 个值。不在表内的平台（雪球、东方财富股吧、知乎等）不采集。

## 三、字段

| 字段 | 填写说明 |
| --- | --- |
| post_id | `EV{事件号}_{平台缩写}_{3位序号}`，全局唯一 |
| title | 原帖标题；非微博取首行前 50 字 |
| content | 正文全文，不写摘要，不写采集说明 |
| channel | 6 类渠道之一 |
| source_platform | 真实来源平台或媒体名 |
| event_type | 事件类型，同事件参数 |
| post_url | 原帖或原文链接 |
| author_name | 账号昵称、媒体名或机构名 |
| author_uid | 平台内部 ID，能取则填 |
| author_fans | 粉丝数，页面显示才填，保留原格式 |
| author_ip_location | IP 归属地，页面显示才填 |
| publish_time | `YYYY-MM-DD HH:MM`；只有日期填 `YYYY-MM-DD 00:00` |
| like_cnt | 点赞数，平台不显示留空 |
| comment_cnt | 评论数，平台不显示留空 |
| repost_cnt | 转发数，平台不显示留空 |
| collect_cnt | 收藏数，平台不显示留空 |
| is_repost | 是否转载，true / false |
| keyword_match | 命中的检索关键词串 |
| topic_tag | 事件级话题标签 |
| topic_list | 事件级话题列表 |
| capture_date | 抓取日期 `YYYY-MM-DD` |

字段顺序固定，不新增字段；没有的字段留空或 null。

## 四、正文与互动量

- `content` 必须是原文全文。社媒取原帖全文，媒体取文章正文，官方源取公告/新闻稿全文。
- 抖音只放视频文案；没有转写就不补。
- 互动量按页面实际显示记录，不估算、不推算；平台不显示的指标留空。
- `author_fans` 页面显示才填；不显示就留空，不用其他指标推算。

## 五、垃圾信息过滤

采集和录入时先过滤，命中以下任一类型直接不录入：

| 类型 | 判定 |
| --- | --- |
| 招聘 | 校招、社招、内推、笔试、面试、简历、岗位、实习 |
| 营销广告 | 促销、开户、课程推广、返现、拉群、代客理财、荐股 |
| 撞名主体 | 与事件主体同名的其他企业或产品，且正文没有事件主体、关联公司或事件特征词 |
| 无有效内容 | 只有标题、一句话、纯表情、纯符号、纯@、纯话题标签；或只有搜索结果页、首页、APP 下载页 |
| 重复 | 同一来源页面重复提交；同一渠道内标题和日期完全相同的转载 |
| 无关泛内容 | 只提行业词，不提事件主体、关联公司或事件特征词，无法判断与事件相关 |
| 无法核验 | 链接打不开，且没有标题、时间、渠道或正文摘要可供核验 |
| 隐私 | 正文含手机号、身份证、住址等个人隐私 |

以下内容不按垃圾信息删除：

- 负面、质疑、批评、情绪化表达，这些是舆情本身。
- 事实可能有误、但确实在讨论事件的帖子，保留，但不能当作事实引用。
- 互动量低、粉丝少的帖子，不是垃圾。
- 与主流观点不同的帖子，保留。
- 官方通稿、公司公告、媒体转载，属于舆情，保留；转载记 `is_repost=true`。

拿不准的保留，不因为不好判断就丢；只删除明确命中上表的内容。

## 六、质量与核验

- **历史事件复现以固定采集清单为准**：每个已冻结事件带一份 `EVT-00N_采集清单.json`（post_id → URL/平台原生 ID/发布时间，URL 级锁定）。复现时打开清单里的页面逐条核验并存快照，**不通过关键词搜索召回**——清单即全集，不会新增也不会缺失。快照清单（snapshot_meta.json）保存采集时的逐帖金标准值（topic_tag/topic_list/keyword_match/互动量等），参数卡只作兜底；回放产物与正式数据逐字段一致（事件 1、13 已实测 0 差异）。
- 每条记录都能回到原页面；打开原文核对标题、时间、正文、来源。
- 一条记录对应一个来源页面；不同渠道的转载分别记录，标题和日期完全相同的不重复录。
- 不臆造金额、日期、比例、互动量；页面打不开或字段不显示时留空。
- 官方源直接使用政府、监管机构、交易所、公司官网的页面或公告 PDF。
- PDF 直链反爬时，优先找同一份报告的完整转载页补齐正文，并保留原链接。
- 采集完成后检查：渠道是否在 6 类内、正文是否全文、时间是否在窗口内、互动量是否为空值。

## 七、文件命名

| 文件 | 用途 |
| --- | --- |
| `EV{事件号}_raw.json` / `.csv` | 主文件，按事件窗口和渠道规则筛选 |
| `EV{事件号}_raw_full.json` / `.csv` | 完整清洗版，保留所有符合渠道规则的记录 |
| `EV{事件号}_post_id_mapping.csv` | post_id 与来源页面的映射 |
| `EV{事件号}_raw_字段说明.md` | 本次采集的字段与口径说明 |

## 八、采集流程

1. 填写事件参数，确定事件号、窗口、主体、别名、关键词和排除词。
2. 只在这 6 类渠道内逐平台检索，记录真实来源名。遇到需要登录或验证的平台（如微博、小红书、抖音），先调出登录界面，等用户完成登录后再继续；不要反复刷新或重试，避免卡死。
3. 打开原文，核对标题、发布时间和正文；按垃圾信息规则过滤，命中直接不录入。
4. 复制正文全文，补齐作者、粉丝数、IP、互动量。
5. 按 6 类渠道归档，确认 `channel` 只出现这 6 个值。
6. 去重并检查字段完整性。
7. 导出 JSON/CSV，更新映射文件。
