① 给一个主题，生成事件参数卡

参数卡定死：事件号 / 8 类事件类型 / Day0–Day1 窗口 / 主体与别名 / 检索词 / 排除词。 有 LLM key 时由模型生成，没 key 时出规则兜底最小卡（会明确标出来）。

② 跑一趟：采集 → 结构化 → 舆情看板

快照回放是本机唯一零依赖、离线、可复现的采集方式：它按 《采集规则》的三层硬过滤（窗口 / 排除词 / 必选词）从原文快照里回放，产出 21 字段 raw。

③ 新事件：检索作业（开单 → 按单落档 → 收单）

②那一套要有现成的原文快照才能跑。这一步补的是更上游： 一个新主题的快照从哪儿来。采集侧这一段是人工 + AI 辅助检索（不是平台 API 抓取）， 所以这里不假装有爬虫 —— 而是把它做成可开单、可收单的作业：
开单 → 照《检索作业单.md》检索并落档 → 收单校验 → 自动接上 ②那一套。 开出来的空作业直接收单会失败（H1d 快照非空），这是对的 —— 0 条不算收单成功。
