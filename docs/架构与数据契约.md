# 架构与数据契约

这份文档说明三件事：五段流水线各自做什么、每一道闸在拦什么、以及**仿真层与报告层之间那份字段契约**。

---

## 一、五段流水线

| 段 | 入口 | 产物 | 闸（不通过即硬停） |
|---|---|---|---|
| ① 采集 | `采集层/采集链.py` ／ 前置 `检索作业.py` | 21 字段原始帖 JSON、结构化标注后的成品 | 成品条数 > 0；字段齐全；未命中去重规则 |
| ② 图谱 | `graphrag/02_代码/跑新事件.py` | 事件包、槽位表、名册、t0 状态快照 | 事件类型可得；捏人完成；当事人识别完成；名册非空 |
| ③ 仿真 | `引擎/跑全轮.py` | 逐轮快照 `t{N}状态_第{N}轮.json`、`round_snapshot.jsonl` | t0 输入齐全（六项）；每轮动作合法 |
| ④ 报告 | `报告/生成报告.py` | `_viz_data.json`、报告 HTML | 报告渲染段数与预期一致（不是看 exit code） |
| ⑤ 前端数据 | `前端数据/生成前端数据.py` | `board.json`、`graph.json` | 两份文件都落地；中心实体取不到即报错 |

编排器 `端到端/跑端到端_v3.py` 支持用 `--from / --to` 指定起止段，便于调试与增量复跑。

**为什么是子进程而不是 import**：编排器会 `sys.exit()`、会改 `sys.path`、会清空自己的输出目录——那是命令行工具的行为，不是库的行为。子进程跑，一条链崩了只崩这一条，后端不受影响。

## 二、仿真层：每轮八步

```
1  承接上一轮状态，轮初衰减（向画像基线回归）
2  合成群体情绪偏离：效价与唤醒双维，权重 2 : 1
3  按偏离确定本轮上场名额：基准 9%，上下限 3%–20%
4  按作息硬门抽样（谁在这个点本来就不该上线）
5  为每个上场者划定视野：只看相关度最高的 5 条
6  调模型在候选动作集内选一个动作
7  轮末刷新情绪：向群体均值传染，并按动作强度回写
8  落盘本轮快照
```

**三个实现约束，各解决一个问题**

| 约束 | 解决什么 |
|---|---|
| 名额随情绪浮动 | 让参与规模与情绪强度同向变化，而不是每轮固定几百人齐刷刷发言 |
| 视野受限（Top-5） | 避免「每个人都看得到全局」，这是仿真区别于统计外推的关键 |
| 固定随机种子 | 同输入同种子可复现，是回测的前提 |

**时间轴**：42 轮 × 4 小时 = 168 小时（完整 7 天），等长切分。
**发帖时机**：发帖只在 t0 注入轮发生，之后全部是对已有内容的反应（引用 / 转发 / 评论 / 点赞 / 沉默）。

## 三、仿真层 → 报告层的字段契约

报告层**不重新分析文本**，只消费仿真层落盘的结构化字段。这是本项目最重要的一条设计：先确定报告要回答什么判断，再倒推仿真层必须落哪些字段。

| 报告模块 | 需要的信息 | 仿真层交付的字段 |
|---|---|---|
| 一 · 传播路径图谱 | 每条帖落在哪个渠道、由哪条帖引用而来、何时发布；哪几轮新增了跨渠道边 | 每帖 `channel` / `channels`（落地渠道集合）/ `quoted_id`（引用上游）/ `publish_time` / `_round`；轮级 `new_cross_channel_edges`；`cross_events`（转载事件） |
| 二 · 情绪演化曲线 | 逐轮群体效价、负面占比、唤醒；按角色与渠道拆分；发帖那一刻其人的情绪 | `series` 的 `valence_mean` / `valence_mean_online` / `negative_ratio` / `arousal_mean`；帖子上的 `author_valence_at_post` / `author_arousal_at_post` |
| 三 · 关键影响节点 | 逐轮动作量与构成、角色与渠道分布、跨渠道边、轮号对应的真实时点 | `post_cnt` / `flow`（评论+转发+点赞）/ 每轮帖子的角色与渠道聚合 / `new_cross_channel_edges` / `window`[起,止]；引用森林派生出度·深度·介数·特征向量 |
| 四 · 风险等级 | 发声人数、动作强度加权互动、新生帖介数峰值 | 上述字段归一化后按 5 轮窗口合成 S |
| 五 · 应对建议 | 事件类型、涉事主体、关键节点轮次、渠道、影响倍数、预警首现轮 | 元数据 `event_type` / `subject` ＋ 模块三、四的现算结果 |

**一句话**：仿真层交付的是一份**带渠道、带引用上游、带情绪、带真实时点、带角色构成的轮级状态序列**。
五类结构缺任何一类，报告都算不出来——① 传播网络结构 ② 逐轮双维情绪 ③ 轮级动作与角色构成 ④ 轮号到真实时点的映射 ⑤ 事件类型与涉事主体。

## 四、报告层三步

```
viz_extract.py   快照 → _viz_data.json      （只做抽取与归一，不做判断）
viz_alert.py     三维度八项观测量 → S        （风险分级与预警首现）
viz_build.py     _viz_data + alert → HTML    （五模块渲染，事件参数化）
```

**渲染验收不看 exit code**：`生成报告.py` 返回 0 只代表脚本跑完，不代表报告渲染完整。
真实验收要在 node 沙箱里把渲染后的 DOM 抓成纯文本逐句通读，或至少校验渲染段数与 `SEC_ERR` 计数。
本项目不止一次遇到过「Python 侧 exit 0、页面只剩骨架」的情况——根因是内联 JS 在某份数据为空时抛异常，掐断了整个 `<script>`。

**换事件即印错**：报告里最容易出问题的地方不是算错，而是**写死**。
例如「最主要的跨渠道跳板」一度是拿「发帖最多的渠道」来回答转出问题的，在有跨渠道传播的事件上恰好能蒙对，在没有的事件上就会印出「微博是跳板，0 起从它转出」。
现在这类断言全部改成现算 + 分支：拿不到就换一句话，而不是印一个自相矛盾的数字。

## 五、口径约定

| 项 | 约定 |
|---|---|
| 角色 | 5 类：网民 / 客户 / KOL / 媒体 / 监管 |
| 渠道 | 6 个：微博 / 抖音 / 小红书 / 新闻门户 / 黑猫投诉 / 监管通报 |
| 槽位 | 角色 × 渠道 = **15 个有效格位**，每格人数由事件热度推算 |
| 事件类型 | 8 类，唯一来源是采集侧，随成品以 sidecar 文件携带，取不到即报错而不是猜 |
| 情感口径 | **发布者本人褒贬**。纯转发 / 转述通稿判中性，不因事件本身负面就判负面 |
| t0 | 取 `max(publish_time)`，即最后一个发帖者的时间 |
| 卷入度 | 当事人 1.00 / 发帖人 min(0.75, 基座+0.10) / 围观取基座 |

口径统一这件事的成本远高于写代码：同一条帖子在不同模块里被赋予不同的角色、渠道或情感，是最难查的一类缺陷——它不报错，只是悄悄把结论带偏。
本项目的做法是**每条口径只允许有一个真源**，其余模块读它、不重算。

## 六、前端：逐段点亮

前端不是流水线的末端，而是贯穿全程的呈现层。

| 时机 | 后端动作 | 使用者看到 |
|---|---|---|
| 采集段结束 | 看板先烘到暂存区 | — |
| 图谱段结束 | 搬进事件目录 + 烘图谱 | 看板有数、知识图谱可看，仿真尚未开始 |
| 仿真进行中 | 每轮写快照 | 回放页轮次与进度条跟真实轮次走 |
| 报告段结束 | 报告 HTML 落盘 | 报告页与预警弹窗同时就绪 |
| 前端段 | 兜底重烘两份 | 与前面完全一致（现算，不是拷贝） |

失败不拦链：某一页的数据没烘出来，只记一笔，链路继续——页面自己会回落到内置数据并显示来源徽标。

**工程约束**：前端构建为纯静态产物，**零外链、零 CDN**，可内网离线运行；后端为零第三方依赖的标准库服务。
这是命题的硬性要求（内网化、不依赖公网、数据不出域），也是本系统能被真实客户部署的前提。
